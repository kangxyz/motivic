# Agent instructions

- Develop motivic cohomology and its reusable foundations. Read [architecture](doc/ARCHITECTURE.md) and [naming](doc/NAMING.md) for ownership decisions; use exact source families for bounded work.
- Reuse Mathlib and Aglib objects and canonical maps. Keep one implementation per declaration, precise lower-leaf imports, and native mathematical declaration namespaces. A module path is not a mandate to wrap native objects in `Motivic`.
- Preserve complete hypotheses, coefficient universes, degree conventions, signs and original maps. A supplied theorem-family input remains an input until proved. Use [interface boundaries](doc/INTERFACES.md).
- Use modern `module` headers, precise `public import` and exposed public sections where needed. Production must never import tests, research snapshots or downstream applications.
- Write maintained text, identifiers and comments in English. Use `Authors: kangxyz` for code authored by this project owner; preserve concrete upstream authors, licenses, source notices and provenance when adapting sources. Imported historical documents are records, not active task instructions.
- Follow [development](doc/DEVELOPMENT.md). All normal workflows, including maintenance, review, merge, integration and publication, must use incremental checks for changed leaves and actual affected consumers. Retain compatible caches and evidence; obtain matching caches before compiling genuinely missing required targets. Relocation, merging, publication, a changed pin or a missing receipt does not justify whole-library rebuilding. Full rebuilding/replay requires an explicit request for that exact scope or exceptional recovery from diagnosed untrustworthy artifacts with no usable matching cache. Cache presence and old logs do not prove current compatibility.
- Incremental validation includes applicable compilation, declaration/text-style lint, affected `MotivicTest` and client tests, and source/trust checks. Compilation covers only the lint or tests it actually runs; separate checks need their own applicable coverage.
- During development, use incremental compilation and its diagnostics, keeping compiler-integrated checks enabled. Independent lint and tests run only in the task's final validation before delivery. Helper returns, internal commits and merges do not trigger them. Reuse compatible evidence and rerun only failed or newly affected checks after final-check repairs.
- Update the owning family README when its interface changes. Cross-family rules belong in `doc/`; create occupied structure for current consumers, without speculative directories or replacement object hierarchies.
- Preserve other contributors' work and exact write ownership. Coordinate mutable dependency/build outputs and serialize Git mutations. Push only with an explicit current request.
- Keep strict A1 invariance, positive-characteristic diagonal comparison, higher-Chow and spectrum comparisons within their documented open boundaries. Do not turn a checked conditional theorem or a failed search into a stronger completion claim.
