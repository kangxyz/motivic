# Agent instructions

- Develop motivic cohomology and its reusable foundations. Read [architecture](docs/ARCHITECTURE.md) and [naming](docs/NAMING.md) for ownership decisions; use exact source families for bounded work.
- Maintain reusable general theory in `Motivic/Aglib/`, mirroring its intended upstream mathematical subject. Candidate declaration namespaces are native mathematical namespaces; their closure may import only Mathlib, Aglib and designated general candidates. Keep ordinary motivic applications outside this subtree. Do not create a package-root `Aglib/` shadow. General curve, line-bundle, frame and pencil interfaces remain candidates when their complete hypotheses and maps are general.
- Reuse Mathlib and Aglib objects and canonical maps. Keep one implementation per declaration, precise lower-leaf imports, and native mathematical declaration namespaces. A module path is not a mandate to wrap native objects in `Motivic`.
- Preserve complete hypotheses, coefficient universes, degree conventions, signs and original maps. A supplied theorem-family input remains an input until proved. Use [interface boundaries](docs/INTERFACES.md).
- Use modern `module` headers, precise `public import` and exposed public sections where needed. Production must never import tests, research snapshots or downstream applications.
- Write maintained text, identifiers and comments in English. Use `Authors: kangxyz` for code authored by this project owner; preserve concrete upstream authors, licenses, source notices and provenance when adapting sources. Imported historical documents are records, not active task instructions.
- For ordinary proof work, use the [normal task](docs/DEVELOPMENT.md#normal-task): one author proves, compiles changed leaves and repairs. Preserve compatible caches/evidence; recover actual missing dependencies instead of broad rebuilding. All normal maintenance, merge and publication stay incremental. Full rebuild/replay requires an explicit request for that scope or diagnosed untrustworthy artifacts without a matching cache.
- At final validation, use `scripts/validate.py --base BASE` (add `--head HEAD` for a clean committed range): selected providers and their lint precede affected tests/consumers/clients. Keep enabled checks and applicable source/trust coverage; compilation supplies only the checks it actually runs. Tooling regressions apply to changed tools. Reuse successful coverage after repair; export only the verified selection without compilation. `--full` selects separately requested diagnostics.
- A lemma, helper return, internal commit or merge does not trigger final validation. Documentation, inventories, cache delivery and cleanup are separate work only when their own purpose requires them.
- Keep `docs/` concise: package-wide summaries, conventions and indexes. Put mathematical definitions, complete hypotheses, universes, signs, API examples and remaining theorem inputs in the owning source-family README or child document. Update that owner when its interface changes. Create occupied structure for current consumers, without speculative directories or replacement object hierarchies.
- Preserve other contributors' work and exact write ownership. Coordinate mutable dependency/build outputs and serialize Git mutations. Push only with an explicit current request.
- HI-presheaf Nisnevich sheafification is available through `Motivic.Cohomology.A1.Sheafification.HomotopyInvariance`; its strict perfect-field corollary is in `Motivic.Cohomology.A1.Sheafification.StrictInvariance`, retaining ordinary HasExt and coefficient universe `u + 1`. The already-HI transfer-sheaf endpoint remains in `Motivic.Cohomology.A1.StrictInvariance.PerfectField`. Keep nonperfect strict invariance, positive-characteristic diagonal, higher-Chow and spectrum comparisons within their documented boundaries. Conditional helper interfaces retain their explicit inputs.
