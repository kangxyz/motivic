# Focused developer tools

Use Python 3.11 or newer from the repository root. During development, use
incremental compilation and its integrated diagnostics. Independent lint and
tests, including applicable tooling tests below, belong only to the current
task's final validation before delivery. Helper returns, internal commits and
merges do not trigger them; preserve compatible results and rerun only failures
or newly affected checks after repairs.

The source checker does not
invoke Lean, modify source, resolve dependencies or validate external proofs:

```sh
python3 scripts/check_repository.py
```

For shared planning (including `validate.py --list`), native wrappers, hosted
phases and Python tooling fixtures, first select an independently reviewed
tooling checkout at the exact revision below:

```sh
export MOTIVIC_TOOLING_ROOT=/absolute/path/to/reviewed-aglib-tooling
export MOTIVIC_TOOLING_REVISION=0caa3a890c9cbeb7ade5e4f804203b31b5b0b3b1
export PYTHONPATH="$MOTIVIC_TOOLING_ROOT/ci${PYTHONPATH:+:$PYTHONPATH}"
python3 -m unittest discover -s scripts -p 'test_*.py'
```

The tooling fixtures need both the shared package on `PYTHONPATH` and the
explicit tooling identity for subprocess adapter checks. This environment does
not change the mathematical dependency pins. The source checker above needs
neither Lean nor shared tooling.

`library_sources.py` inventories occupied `Motivic` and `MotivicTest` sources and
provides the comment-aware Lean import parser adapted from Aglib at revision
`c9863095f90b8bd312af807dbf0e378df82403b5` under Apache-2.0.
`check_repository.py` checks local import existence, actual import cycles,
generated-facade enrollment, production/test isolation, retired source roots, proof-placeholder and unsafe
tokens, package/test identities and exact accepted dependency pins. It separately
checks `examples/downstream` in the client's module namespace: imports may use
production and dependencies, production cannot import the client, and client
placeholders and missing local imports are rejected. The reported source count
distinguishes project and downstream files. Local `Motivic.Aglib` modules own
maintained general-theory candidates that mirror upstream subjects and use native
declaration namespaces. Their imports may use approved external roots (including
Mathlib and Aglib) and other `Motivic.Aglib` modules; imports of ordinary local
`Motivic` host modules, including package and family facades, are rejected at the
candidate edge. Checking every candidate edge also prevents indirect host
dependencies. Host modules may import candidates, and the complete local import
graph must remain acyclic. This boundary concerns module imports, not declaration
namespaces or mathematical subject names. External roots are allowlisted;
external module existence and elaboration require resolved dependencies and a
focused Lean build. Production module path components must match
`[A-Z][A-Za-z0-9_]*`; this naming guard does not inspect declaration namespaces,
test module names or external imports.

`generate_imports.py` refreshes only existing topic facades explicitly enrolled
with the exact leading marker below, optionally after an initial copyright
header. This ownership convention follows Aglib at revision `3c571e67a3180565bfb4e6e634fb17d0e5b0b9e1`; its
exhaustive-root behavior is deliberately not used here.

```lean
-- Generated by scripts/generate_imports.py; do not edit by hand.
module
```

The same-named directory must contain actual Lean sources. Each enrolled facade
receives sorted modern `public import` lines for every existing descendant Lean
source, including nested facades. Leaf implementations, unmarked manual facades
and absent facade files are preserved. Quoted markers and markers after source
commands do not transfer ownership. Existing copyright headers are preserved;
marked implementation commands and legacy children are rejected. All proposed
facade edges are checked together for import cycles before any write, including
cycles through implementations that import the facade. Finish concurrent source
edits before generating; the tool rechecks its plan but does not lock editors.

```sh
python3 scripts/generate_imports.py
python3 scripts/generate_imports.py --check
python3 -m unittest discover -s scripts -p 'test_generate_imports.py'
```

Both commands accept `--root PATH`. The check command and repository checker
report stale enrolled facades without writing. There is no implicit directory
or root enrollment in this topic generator. The native Mathlib `mk_all` tool
owns the complete `Motivic.lean` production entry. `lake test` discovers the
`MotivicTest.+` library without a maintained `MotivicTest.lean` file. Topic
generation remains limited to its existing marked facades.
The separate global legacy diagnostic is `Audits/Motivic.lean`, outside native
Test discovery; invoke it explicitly with `lake env lean Audits/Motivic.lean`.
`test_generate_imports.py` uses temporary fixtures for ownership, add/remove
tracking, curated roots, prospective cycles and repository enrollment.

`cache.py` requires explicit existing local module targets. It follows their
imports through local source and the pinned Aglib source to collect only
reachable Mathlib cache roots. It never sends Aglib modules to Mathlib's cache
and rejects an unscoped `Mathlib` import. `--list` prints the selection without
running Lake; `--resolve-deps` resolves the existing manifest before fetching:

```sh
python3 scripts/cache.py --resolve-deps Motivic.Cor
python3 scripts/cache.py --list Motivic.Cor
```

`--guarded` applies the reviewed Aglib resource guard and writes a private cache
receipt for a direct invocation. Shared local validation and CI instead run the
focused cache command as a capped task under the shared executor, with their
separate tooling checkout and memory limits.
`cache_bootstrap.py` permits the cache executable's cold-start compiler fanout
with one-thread compiler caps and the same finite heap and group RSS limits.
It accepts only focused cache acquisition for existing Mathlib/Batteries leaves
and checks the reviewed upstream helper bytes before loading them.
`--lint-runtime` also fetches the pinned style driver's exact direct Mathlib and
Batteries prerequisites. Lean and Lake come from the toolchain; the optional
Cli and ImportGraph support leaves retain their temporary isolated compilation.

`build.py` requires explicit targets and calls the shared `lean_ci.build` helper
through `build_modules.py`. Bare semantic module names are validated as local
sources; the common Lake boundary renders `+MODULE` for both cache probes and
builds. The former byte-locked monkey patch is removed. Cache misses retain the
shared helper's guarded selected-graph build and failure receipts.

`MOTIVIC_TOOLING_REVISION` to its exact reviewed 40-hex commit. The entry verifies


the package root. `MOTIVIC_BUILD_THREADS`, `MOTIVIC_LEAN_MEMORY_MB` and
`MOTIVIC_RSS_LIMIT_MB` retain precedence over the older `AGLIB_*` aliases.
The explicit inherited remote wrapper/profile remains owned by its caller.
Keep dependency build trees and outputs owned by this checkout; investigate
unexpected dependency compilation and recover matching caches first.

`test_repository.py` supplies boundary fixtures for actual cycles, cross-subject

`ci_targets.py` selects the same affected scope for CI and local final
validation. Supply a Git comparison, explicit targets, or explicitly opt into
all existing modules with `--full`:

```sh
python3 scripts/ci_targets.py --base BASE --head HEAD --plan /tmp/motivic-plan.json
python3 scripts/validate.py --base BASE --head HEAD --list
python3 scripts/validate.py --base BASE --head HEAD
python3 scripts/validate.py --manual-targets Motivic.Cor
```

The checked-out revision must match `--head`. Local staged, unstaged and
untracked files also enter the comparison. The selector keeps its plain target
list stdout and optionally writes JSON. The selector's optional `--github-output`
also emits deterministic gzip/base64 target and plan outputs. The hosted shared
workflow instead keeps its plan in runner-owned external state and emits the
native-phase boolean to GitHub Actions. The local validation adapter
reselects a transported plan against its recorded comparison before using it.
A changed plan fails before native commands; select the current affected scope.
`--list` prints shared task declarations without executing native tools, resolving dependencies,
compiling, touching caches or creating receipts.

Every current changed local module and every existing reverse-reachable local
consumer is selected, including implementations, public facades, tests with
declarations and optional leaves outside curated roots. Deleted/renamed names
remain graph seeds, but absent sources are never build targets. Unrelated roots
and tests are excluded. Test-only changes retain their direct production
prerequisites for provider checking. Client source/configuration selects its
actual local imports and client acceptance; a changed public import selects
the independent client too. A root is selected when it is actually changed,
required by the client, or reached as a consumer.

After a verified baseline has been admitted, documentation and evidence JSON
changes select static source checks without Lean installation, dependency
resolution, compilation, lint, cache restoration or publication. Explicit
initial enrollment still requires every local native target and the client.
Execution-script and CI-workflow changes select affected Python
fixtures and static checks. If no native scope is already selected, they also
compile the exact curated `Motivic` and `MotivicTest` facade modules, run their
declaration/style checks, and check the independent client. The module build
adapter uses `+` selectors; this smoke check does not select whole libraries or
expand unchanged test prerequisites. Existing Lean, pin-upgrade and manual
native scopes keep their exact target, provider, style and client selection.
Markdown and pure `test_*.py` fixture changes do not request this native smoke.
Shared parser/workflow and unknown Python/shell tools select all current tooling fixtures. Build, cache, client
and selector changes also select `test_validate.py`. Missing push bases use an available trusted default-branch merge-base, or the
root diff of a true initial commit. CI supplies the repository default branch;
local selection can use `--default-branch` or Git's origin/HEAD. An unresolvable
base fails actionably. Manual dispatch, unknown paths and cache misses never
imply full acceptance.
Changed dependency/toolchain configuration requires explicit target scope or
`--full`; identify invalidated coverage and restore matching caches first.
A full diagnostic selects all occupied local modules, including optional leaves.

For an automatically checked reviewed Aglib pin upgrade, commit one current
`.github/dependency-scope.json` record with this exact version 1 schema:

```json
{
  "version": 1,
  "dependency": {"name": "Aglib", "before": "OLD_40_HEX_REV", "after": "NEW_40_HEX_REV"},
  "before": {
    "lakefile.toml": "OLD_SHA256", "lakefile.lean": null,
    "lake-manifest.json": "OLD_SHA256", "lean-toolchain": "OLD_SHA256"
  },
  "after": {
    "lakefile.toml": "NEW_SHA256", "lakefile.lean": null,
    "lake-manifest.json": "NEW_SHA256", "lean-toolchain": "NEW_SHA256"
  },
  "targets": ["Motivic.Selected.Provider"]
}
```

Use lowercase full revision/hash strings; `null` means the file is absent.
Both configuration maps must include every listed path. Targets are unique,
existing local module seeds whose dependency impact has been reviewed. The
selector verifies the old bytes at the resolved Git comparison base, the new
checkout bytes, and both Aglib pins in the lakefile and manifest. Missing,
malformed or mismatched records fail closed. Accepted seeds join changed Lean
sources and use the ordinary reverse-consumer and client selection. Unchanged
test seeds retain their compilation and lint coverage without adding unrelated
production prerequisites; actually edited tests still select those prerequisites,
as do ordinary explicit manual test targets. The transported plan binds the
record's SHA256 and revalidates it before execution. This records reviewed
scope, not successful compilation or a proof of scope completeness.
The record is consulted only for a non-initial configuration change without
explicit manual targets or `--full`. Later pushes without configuration changes
ignore a retained record; replace it when reviewing the next pin transition.

`validate.py` runs final acceptance only when requested. The thin
`shared_workflow.py` adapter declares scope and predicates through
`lean_ci.recipe.native_recipe`; `Application.check` owns execution, resource
guarding, receipt verification and compatible individual-check continuation: static checks and affected tooling fixtures, focused
matching cache acquisition, provider compilation, provider declaration and style
lint, affected consumer/test compilation, remaining affected declaration-origin
lint, then the affected client. The latter includes unchanged consumer sources
whose imported environments changed, and reuses completed provider lint.
Text/style checks retain their changed-source scope. A failure stops dependent phases. For declaration lint,
`lint_declarations.py` adds a checksum-guarded exact defining-module filter to
the pinned Batteries driver, with explicit origins and `--no-build`. Its native
package-prefix enumeration alone includes imported origins. The adapter retains
all enabled native linters (including slow checks), nolints and failure handling;
providers and remaining affected consumers are disjoint origins. Import-only
origins may have zero declarations; this pinned Batteries version accepts empty
input, while their compilation and style checks remain selected. `--full` keeps
the native diagnostic route. The reviewed Batteries driver revision is
`f2effa3d803fda822b1f97b806c47cf2adfbcbc2`; source drift fails before native execution.

Ordinary declaration validation has one checkpoint task per defining origin,
using the unchanged checker with `--root ROOT --no-build ORIGIN`. Every origin
still imports into its own fresh Lean process. The shared executor may schedule
an explicitly read-only batch at up to eight checks within an admitted managed
profile's existing job cap; local execution, including the hosted workflow,
uses one check at a time. Successful individual checks are recorded even when
a later origin or an active peer fails. The phase remains failed until every
required check succeeds. The full/native-package diagnostic is unchanged.

This is compiler/linter/test coverage, not independent kernel replay or a proof

The shared final check enrolls local source candidates, absent configurations,
policy and actual checker/runtime inputs before selection. It binds dirty
worktree bytes and preserves strict committed-source CI as a separate envelope.
Receipt state, optional `--progress` stores and `--outputs` exports must be
outside the checkout; omitted state uses an external temporary directory.
Keep the same external progress store when continuing compatible final checks.

Hosted native validation passes `--progress "$RUNNER_TEMP/motivic-check-progress"`.
The workflow restores and saves that directory in a separate cache namespace
bound to runner OS/architecture, the reviewed tooling revision and the
toolchain/configuration/CI-policy hashes, with a unique run/attempt key. The
save step is configured to run after failed validation when a cache key was established.
Restoration supplies candidate records only: each origin's complete current
binding, including checker policy, source closure, native artifacts, reflected
runtime and compiler identity, must match before reuse. Build caches do not
substitute for check records. An incomplete phase cannot finalize or publish.
Manual reruns can continue compatible successes; no automatic rerun loop is
configured. The native step still has a 300-minute limit within a 360-minute
job. Complete first-run enrollment is not promised to fit that interval, and
actual complete hosted timing remains unmeasured.

The parsed local import graph is memoized only within its guarded whole-source
observer lifetime. Source-directory enrollment and every source byte are
observed before parsing; additions, removals or source drift reject that
attempt. Individual source/native/runtime bindings remain separate and current.

For a clean admitted committed checkout with the independent tooling environment
configured, the hosted entry is:

```sh
python3 scripts/shared_workflow.py plan --state /absolute/scratch/ci-state \
  --repository kangxyz/motivic --default-branch main --head "$(git rev-parse HEAD)"
python3 scripts/shared_workflow.py source --state /absolute/scratch/ci-state
python3 scripts/shared_workflow.py native --state /absolute/scratch/ci-state
python3 scripts/shared_workflow.py finalize --state /absolute/scratch/ci-state \
  --outputs /absolute/scratch/native-outputs.jsonl
```

Skip `native` only when the plan requires source alone. Finalization reconstructs
all required task receipts before writing native mappings and the matching
`.coverage.json` sidecar. Publication requires successful finalization; partial
failed native checks still save dependency, root/client build and native cache
progress. Cached outputs alone supply no verification evidence. Initial full
enrollment can expose pre-existing optional-leaf failures; such a failure blocks
the first baseline and publication while preserving partial progress.
